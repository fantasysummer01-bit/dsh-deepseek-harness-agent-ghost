# Ghost 主体状态运行层

本文记录 0.3.0 的内部实现契约与边界。插件页面和 README 保持简短的原理介绍，不增加任务或人格设置面板。

## 主体与对话

同一份 Ghost 数据只有一个持久 `ghostId`。不同 DSH 对话是这个 Ghost 的不同工作现场，分别保留当前关注、来源事件和任务关联，共享身份、人格观察、长期记忆与持续任务。创建新对话不创建另一个人格。

主体状态补充了“正在做什么、答应过什么、进展到哪里”。DSH 仍负责创建和驱动会话、选择模型、执行工具及管理审批；Ghost 不替换这些宿主能力。

## 事件与状态

只有已授权并提交的可见用户消息和模型回复可以形成来源。原始事件保留其角色、会话、时间和事件 ID；工具秘密、推理内容、注入上下文和子代理消息不因本次升级自动进入记忆。

可识别的请求、承诺和进展经保守规则更新主体状态。原始事件、状态版本及对应主体变更在同一个 SQLite 事务内提交；其中任意一步失败时全部回滚。重复消息不重复建立任务。

用户请求、用户报告与模型说法保持不同来源。助手承诺可以作为承诺记录，助手自称完成只记为模型报告，不能单凭该说法把用户任务升级为已验证完成。规则不能确定指代时保留歧义，不能把另一个对话中的任务擅自完成或取消。

## 回复前后

回复前，Ghost 从已提交状态构造有界上下文，提供当前对话任务、相关的全局持续事项和人格、记忆线索。上下文装配只读，不因为重复装配、模型重试或新窗口查询而产生新经历。

回复后，Ghost 接收 DSH 已提交的模型可见输出，将其中的承诺、进度或完成说法作为带来源的报告记录。这个闭环保存了主体对工作的连续认识，不代表模型报告已经由外部工具验证。

复杂语言理解仍可使用 DSH 配置的 LLM。Ghost 保存状态并提供约束，LLM 提供当下的理解与表达。

## 主体工具与并发

在宿主提供相应工具服务时，`ghost_state` 读取主体及当前对话的工作状态，`ghost_task` 更新有来源的任务信息。工具调用受当前会话范围、Ghost 启动状态、健康状态和卸载状态约束，不能修改权限或宿主配置。

主体具有独立版本。任务写入根据读取到的主体版本进行比较后提交；过时的写入被拒绝，调用者必须重新读取状态。多个聊天共享一个主体，不允许一个迟到的模型结果覆盖另一个对话已提交的新进展。

任务创建与状态更新还要依据本对话最新的真人消息，不能在用户暂停或取消之后重用旧请求。规则无法直接识别的明确请求，可由模型提出任务标题，保存为 `model_interpretation`；它不等于用户原文。

任务工具维护任务状态，不授予任意执行权限。模型说法不会因经过工具接口而变成用户同意或外部执行证据。

## 持久化与恢复

主体状态与已有身份、事件、账本和检查点共同保存在 Ghost 数据中。旧 schema 1 数据通过追加主体初始化和变更记录升级，保留原 Ghost ID、旧账本哈希和检查点，不改写既有审计快照。

初始化与恢复仅使用 Ghost 已经授权保存的来源；不扫描或导入旧 DSH 聊天。变更回放必须根据来源事件或已记录命令确定性恢复，不在重启时重新调用模型猜测过去。

未完成任务与承诺不会随 15／60 天的记忆分层自动遗忘。事件的召回表示可以压缩，未结事项仍保留到有依据的完成或取消。数量边界不能静默丢弃未完成工作。

原型主体摘要上限为 512 个对话、256 项任务、128 条承诺。任务容量满时只回收最早完成或取消的摘要，承诺只回收已解决历史；原事件及旧账本仍保留。活跃事项满额时保留原有内容，并记录容量诊断或拒绝工具命令。退役请求标记保留最近 512 条，自动事件另由提交序号去重。它不是无限容量的任务调度系统。

核心导出随持久状态包含主体信息；卸载仍按已确认的 Ghost 自有数据范围处理。旧程序不能安全理解新增账本迁移类型；回滚需要升级前的一致备份。

## 运行边界

- 本次补充统一主体状态、任务关联、报告回写和上下文闭环，未全面接管 DSH 调度。
- 没有后台自主执行、自动开启聊天或停机期间持续思考。恢复未完成工作的信息，不等于自动继续执行工作。
- 自然语言提取为保守规则，可能漏记或留下歧义；不将规则推断冒充用户原话。
- DSH 的模型选择、工具执行、权限与审批继续有效。未完成工具或未取得外部证据时，不声称任务已实际执行成功。
- 可以验证的是身份、任务、经历与软件状态的连续性，不能据此证明主观意识。
- 生产 DSH 有任务运行时不强制重启。本地安装链接随源码更新，运行中的宿主仍可能需要在合适时机正常重新加载。
