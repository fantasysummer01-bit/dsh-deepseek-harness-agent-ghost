# Ghost 插件更新

本文记录内部更新流程与验证边界。设置页和 README 继续只保留简短原理介绍。

## 检查与下载

只有点击「检查更新」才访问固定公开仓库 `fantasysummer01-bit/dsh-deepseek-harness-agent-ghost`。没有定时联网检查，不要求 GitHub Token，也不发送聊天、人格或记忆内容。

更新源为 `main` 上 `package.json` 声明的稳定 SemVer。只有版本高于当前版本才下载；预发布版、相同版本和旧版本不自动安装。检查先固定提交 SHA，随后按该提交的 Git tree／blob 下载允许的运行文件，校验 Git blob 哈希、字节数及缓存 SHA-256。请求拒绝重定向，并有超时、文件数量、单文件和总字节数上限。哈希用于检查内容一致性，不代表独立签名或代码审查。

下载只允许插件声明、运行代码、更新／卸载 helper 和 README。含额外依赖、安装生命周期脚本、未知入口或宿主配置变动的版本拒绝自动安装；补丁不能更改 Ghost 数据路径或添加其他插件。链接、子模块、保留路径、路径冲突或不完整清单也会拒绝。

## 等待正常退出后切换代码

经校验的代码放在 `DSH_HOME/plugin-updates/dsh-ghost/<version>-<commit>/package`；任务、结果、锁和 profile 备份均放在同一独立代码缓存的 `control` 下。helper 复制到独立临时目录运行，不覆盖正在运行的源码，不执行 `git pull`。

界面显示「更新已准备」表示已经排队，还没有完成安装。helper 等待 DSH 正常退出后，使用 Desktop 自带官方 CLI 的 `plugin --profile desktop add <package> --offline --ignore-scripts` 切换同名插件。它只检查进程是否仍在运行，不强制结束、重启或打断 DSH 任务；等待期间启动／关闭 Ghost 和导出仍可用，重复更新及卸载被互斥保护。

切换前备份当前 Desktop profile 的五个文件：`package.json`、`pnpm-lock.yaml`、`cordis.patch.yml`、`cordis.yml`、`pnpm-workspace.yaml`。安装失败时，在确认 DSH 已退出的条件下尝试恢复旧代码链接及这五个文件，并报告失败。如果回退本身失败，会明确报告，不能视为更新完成。更新记录与备份可能含本机路径或 profile 配置，不应提交或随插件发布。

明确重试会创建新的控制任务，重新保存当前配置，仅复用验证过的代码。中断任务有未完成备份时，先验证配置仍与快照一致；冲突则停止，避免用过时备份覆盖后来修改。只有完整恢复并校验后，旧备份才允许在同任务重试时归档。回退失败会持续显示错误，不能被新版本链接或后续版本检查掩盖。

## 核心记录保持独立

更新器只解析受保护核心目录的路径以检查隔离关系，不打开、枚举或改写该目录内的记忆文件。它与 helper 不读取、迁移、检查点处理或删除核心 SQLite、WAL、SHM、人格、任务及账本。更新控制锁自己的 SQLite 位于代码缓存，与核心数据库分开。路径重叠或安装目标发生变化时拒绝继续。

运行中的 Ghost 仍可按原有授权记录新交流；「核心记录保留」是更新过程不修改记忆的约束，不是暂停正常记忆功能。新代码在 DSH 下次正常启动后生效。自动更新不执行核心 schema 迁移；需要新依赖、安装 hook 或调整数据路径的版本须另行处理。

## 验证与边界

- 网络源测试覆盖版本比较、固定提交、Git blob 完整性、下载边界、失败及不兼容包拒绝；更新协调器和 worker 测试使用隔离数据，覆盖互斥、等待退出、缓存／目标变更及失败回退。
- 真实官方 CLI smoke 使用临时 `DSH_HOME` 和 Desktop profile，验证同名 `add` 切换代码、保留旧源码和其他插件配置；核心 SQLite／WAL／SHM／人格哨兵文件逐字节不变。CLI 未运行测试插件，也没有使用生产凭据。
- 真实 GitHub 检查与 blob 下载验证只将公开文件放入内存，没有执行下载代码或更新生产插件。浏览器预览使用演示数据；测试「待退出」不代表生产安装已经完成。
- 生产 DSH 未执行此次自动更新、卸载或强制重启。具体测试结果见 [验证记录](ACCEPTANCE.md)。
